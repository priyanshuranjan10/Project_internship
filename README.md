# UdaanFest — Inter-College Activities Registration Portal

A B.Tech (CS) mini-project: a centralised web portal for students across
different colleges to register for inter-college Co-Curricular and
Extra-Curricular activities.

**Tech stack:** HTML, CSS, JavaScript, PHP, MySQL (mysqli, prepared statements)

## 2. Database Schema

Five tables (see `sql/schema.sql` for full definitions):

| Table | Purpose |
|---|---|
| `colleges` | College/university name, city, state |
| `students` | Registered student details + hashed password |
| `activities` | Master list of Co-Curricular / Extra-Curricular activities |
| `registrations` | Junction table — many-to-many between `students` and `activities` |
| `admins` | Simple admin login accounts |

`registrations` has a `UNIQUE (student_id, activity_id)` key so a student can
never be registered twice for the same activity, and both `students.email`
and `students.roll_no` are `UNIQUE`, which is what powers the
duplicate-registration check in `register_process.php`.

## 3. Local Setup (XAMPP / WAMP)

1. Install [XAMPP](https://www.apachefriends.org/) (or WAMP) and start
   **Apache** + **MySQL** from the control panel.
2. Copy the whole `udaanfest/` project folder into
   `C:\xampp\htdocs\udaanfest` (Windows) or `/opt/lampp/htdocs/udaanfest`
   (Linux).
3. Open **phpMyAdmin** (`http://localhost/phpmyadmin`) → **Import** tab →
   choose `sql/schema.sql` → Go. This creates the `activity_portal` database
   and all five tables.
4. Open **`http://localhost/udaanfest/setup.php`** in your browser once.
   This script:
   - imports every row of `data/activities_import.csv` into the
     `activities` table using PHP's `fgetcsv()` (per Section 5 of the
     assignment),
   - seeds a handful of sample colleges,
   - creates the default admin account: **admin / Admin@123**.

   *(Delete or password-protect `setup.php` after this step on any
   shared/demo server.)*
5. Check `includes/db.php` — the defaults (`localhost` / `root` / no
   password / `activity_portal`) match a stock XAMPP install. Edit if your
   MySQL credentials differ.
6. Visit **`http://localhost/udaanfest/index.html`** — you're live.
7. Visit **`http://localhost/udaanfest/admin/login.php`** to see the admin
   dashboard (login: `admin` / `Admin@123`).

## 4. Features Implemented

- **Landing page** — hero section, highlights, featured activities, CTA.
- **Dynamic activities page & registration form** — Co-Curricular
  checkboxes and Extra-Curricular multi-select `<select>` are generated by
  a PHP loop querying the `activities` table; nothing is hardcoded.
- **Client-side validation** (`js/validation.js`) — required fields, email
  format, 10-digit mobile number, at least one activity selected, terms
  checkbox.
- **Server-side validation** (`register_process.php`) — re-checks every
  field, uses `mysqli` **prepared statements** throughout (SQL-injection
  safe), rejects duplicate email/roll number, hashes passwords with
  `password_hash()`.
- **Optional ID card upload** — validated by extension and size, stored
  under `uploads/`.
- **Student login/dashboard** — students can log back in with
  email/roll number + password and add or remove activities at any time.
- **Confirmation page** — shows a summary of the activities just chosen.
- **Admin dashboard** — lists every registration, filter by activity or
  college, per-activity registration counts, CSV export.
- **Security basics** — prepared statements everywhere, `htmlspecialchars()`
  on all echoed output, hashed passwords for both students and admins.

## 5. Customizing the Activities List

Per Section 5 of the assignment, this project's activity list has been
customized with 8 activities relevant to a Katihar, Bihar college context
(on top of the original 33):

**Added — Co-Curricular:** Bihar Heritage Quiz, Maithili Poetry Recitation,
Agri-Tech Innovation Challenge.

**Added — Extra-Curricular:** Kabaddi, Kho-Kho, Bihar Folk Dance
(Jat-Jatin), Maithili Folk Singing, Litti-Chokha Cooking Competition.

To add/remove more activities yourself:
1. Edit `data/Activities_Master_List_Customized.xlsx` (or the original
   provided file).
2. Re-export the two activity sheets to `data/activities_import.csv`
   (columns: `activity_id, activity_name, activity_type, category, level`).
3. Re-run `setup.php` (it uses `ON DUPLICATE KEY UPDATE`, so it's safe to
   run again).

## 6. Known Limitations / Next Steps (Bonus Ideas, Section 8)

- Email confirmation (`mail()`) is stubbed with a comment in
  `confirmation.php` — needs a configured SMTP/sendmail server to actually
  send.
- QR code generation for check-in is not implemented.
- The per-activity counts table on the admin dashboard is plain HTML; wire
  it into Chart.js for a visual bar chart.
- AJAX search/filter on the registration page is not implemented — the
  current activity list uses plain checkboxes/multi-select.
- `index.html`, `about.html`, `contact.html` are static (they don't reflect
  login state in the nav) since they're plain HTML per the assignment's
  page list; `activities.php` and all logged-in pages use the shared
  PHP header that does reflect login state.
